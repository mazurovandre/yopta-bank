ДЗ  🚀 Цель
Целью задачи является реализация REST API на Nest.js. Сервис должен позволять работать с пользователем (CRUD):
1. регистрация
2. получение профилей и профиля
3. обновление профиля
4. удаление профиля
5. вход в систему
   👨‍💻 Действующие лица
   Пользователь
   🛠️ Требования по стеку технологий
* NestJS
* PostgreSQL (Any ORM)
* Docker-Compose
* Git
  ✍️ Задание
  Необходимо инициализировать проект на фреймворке NestJS используя СУБД PostgreSQL, которую потребуется поднять в docker-compose (или docker). Кстати в docker-compose поднимается только БД, а Nest.js приложение запускается в терминале
  1 уровень
  Должен быть работающий проект на NestJS и подключение к PostgreSQL (обязательная СУБД поднята в docker compose / docker)
  На это уровне нужно реализовать регистрацию пользователя. В запрсое на регистрацию пользователь должен передать следующие поля:
* логин
* email
* пароль
* возраст
* описание о себе (до 1000 символов)
  После регистрации пользователю должен выдаваться access_token и refresh_token. Как реализовать токены с помощью NestJS можно найти в документации NestJS или ютубе. Если срок access токена истёк - должна вылетать ошибка 401 и пользователь должен получить новый токен с помощью refresh токена.
  Кроме регистрации пользователь может залогиниться по логину и паролю (пройти аутентификацию и авторизацию). В аутентфикацию входит выдача новых токенов 😎
  Также пользователь должен иметь возможность получить информацию о себе (о своем пользователе): все поля. В роуте получения информации о себе не должно быть параметра “:id”. Должно быть, например, так “/profile/my”, а не “profile/:id” (где “:id” это айди пользователя)
  2 уровень
  Реализовать функциональную возможность получения всех пользователей для авторизованных юзеров. Предусмотреть пагинацию и фильтр поиска по логину
  3 уровень
  Дополнить логику обновлением и удалением пользователя. Удаление пользователя должно быть мягким (Soft-delete)
  😎 4 уровень — гигачад
  Описать Swagger документацию и покрыть тестами.
* Если интересно разобраться в теме интеграционных тестов, можно изучить testcontainers. Но внедрять в домашке необязательно
